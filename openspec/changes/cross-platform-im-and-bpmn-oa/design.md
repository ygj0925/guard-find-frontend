## Goals / Non-Goals

**Goals:**

1. 可恢复、不串号、不因并发漏消息的 IM；可量化的 WS 请求量收益。
2. 鸿蒙按能力分别验收，补齐可安全使用的小工具。
3. 可版本化、可审计、租户隔离的 BPMN OA，完整业务模块分批关闭验收清单。
4. 所有性能改善有前后基线；所有完成声明附测试证据与残留列表。

**Non-Goals:**

- 不把两个已有服务/身份域/数据库直接合并，不默认用户 ID 在两域等价。
- 不把所有 HTTP 接口改成 WS，不建设音视频/群聊，不承诺操作系统后台实时保活。
- 首期不做公众 App/小程序 OA、不做薪税核算/银行支付/ERP 全量会计核算。
- 不开放任意脚本、SQL、HTTP 地址或 Bean 表达式给流程设计者执行。
- 不把候选 SLA 当作已测结果；不在生产数据库跑压测/自动回滚删除引擎表。

## Decisions

### 1. 仓库和交付边界

| 功能                     | 前端                | 服务端             | 身份            |
| ------------------------ | ------------------- | ------------------ | --------------- |
| App IM、小工具、鸿蒙能力 | guard-find-app      | guard-find-server  | /app 用户域     |
| 公寓 IM                  | guard-find-miniapp  | guard-find-backend | /miniapp 用户域 |
| 企业 OA、后台性能        | guard-find-frontend | guard-find-backend | 后台员工与租户  |

共用语义和测试场景，不共享内存状态或复制令牌。OA 使用 backend 现有组织/用户，补员工档案、岗位、直属主管；管理员操作权限不等于替别人签字。

分期：A 消息安全与正确性 → B 鸿蒙和工具 → C 性能基线及审批引擎 → D 请假/报销完整试点 → E OA 其余模块。A/B 可与设计工作并行，C 引擎兼容性是 D 的前置，所有阶段单独提交和核验。

### 2. WebSocket 应如何优化项目

- WS 推送「数据已变化」事件，REST 仍负责鉴权、幂等写入、持久化、分页补拉。敏感 OA 通知只含类型/实例 ID，不下发整张表单。
- 前台且有登录态时维护连接，导航切换可短暂复用；退出/换号立即失效并清空旧订阅上下文。后台暂停轮询与连接，回前台先补拉再恢复实时监听。
- 明确 idle/connecting/open/backoff/stopped 状态；每次建连/失效换代，迟到 open/message/close/fail 一律忽略。
- 小程序显式传 callback 获取 SocketTask，去除将 Promise 当平台不支持的补丁。连接超时、ping/pong 截止时间、send fail 均转 backoff；指数退避带上限，避免紧密重试。
- 在线聊天低频兜底、断线短间隔补拉；重连立即补拉。列表可见时也有兜底；页面离开不能继续自动已读。
- 所有并发刷新汇入单飞队列；发送结果可合并显示但不推进读取游标。超长 ID 使用十进制字符串，消息按 ID 去重，读取游标单调。
- 新消息提交后才发事件；单实例先用 afterCommit 并保留 REST 补偿。多副本时内存连接表仅覆盖本节点，需可靠事件 outbox + 跨节点分发；不将 Redis Pub/Sub 本身当持久消息队列。
- 手握长效 token 的 URL 有日志风险：首批禁止记录完整 URL/凭据、采用 WSS；后续在同批客户端服务端升级中引入短效单用途 WS ticket，不能未经联调仅改一端。
- 后台 OA 的待办计数、导出进度可复用经过鉴权的通知能力；业务事件带 eventId/version，重复投递可幂等应用。通知失败不回滚已经完成的审批。

候选收益验收：单用户静默可见聊天 5 分钟，相比 3 秒固定轮询约 100 次请求，在线目标不高于 25 次补拉；本地健康网络下提交到前端显示 p95 ≤ 1 秒。实际环境测量后才报告收益。

### 3. IM 数据与协议

- 普通会话和客服会话都限制每次读取数量，首页读取最新一页、向前分页查历史，恢复连接按已同步游标向后排空，禁止一次读取全部历史。
- 同一会话写入顺序必须与游标顺序一致：优先借助会话行锁在分配消息 ID 前序列化；客服建立可锁定的会话记录。使用真实 MySQL 并发测试验证迟提交的小 ID 不丢失。
- 已读只覆盖实际返回/用户已看到的消息上界，服务端检查成员资格，并在同一锁定顺序与事务下更新计数，不能无条件清零。
- 保留现有 API envelope；引入上界参数或分页前先确认已部署客户端情况。服务端先兼容必要迁移，再发布客户端，最终收口旧路径，不留永久双实现。
- 验收矩阵：自发/对方同时发、100+ 未读、大 ID、重复事件、断网重连、旧 socket 迟到、令牌过期/退出/换号、隐藏再显示、事务回滚、两个节点、客服与普通聊天。

### 4. 鸿蒙与新工具

鸿蒙优先修持久化（杀进程重启仍保留隔离的合法数据）、安全随机数（无安全源则拒绝生成密码，不降级 Math.random）、上传契约。选图、压缩、复制、分享逐项经 expo-harmony-cli 兼容表接入；不得手动绕过 CLI 安装原生依赖、改托管 patch。若工具链无法生成或缺签名/设备，则登记阻塞，不能标完成。

新增两项纯文本工具，首版不依赖图片或新原生能力：

| 工具         | 用户流程                                       | 数据与约束                                                                                         |
| ------------ | ---------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 灵感便笺     | 创建、编辑、置顶、关键词检索、归档、删除       | note：user_id、title、content、pinned、archived、version、时间；分页，内容长度限制，乐观锁避免覆盖 |
| 物品收纳定位 | 物品录入、位置分类、关键词查找、数量调整、归档 | item：user_id、name、location、quantity、note、version、时间；数量非负，位置全文检索暂不引外部搜索 |

server 在 /app/tool 下提供分页 CRUD，user_id 从认证上下文取得；读取/更新/删除逐条验证归属，客户端不能修改 owner。跨账号/离线失败不得用旧缓存冒充保存成功；MVP 不做复杂离线双向同步。

### 5. 后台性能治理

先测再改：用户角色装配记录每页 SQL 次数；房源真实筛选和排序做 EXPLAIN ANALYZE；文件 COUNT/SUM 查扫描量；权限菜单失效观测回源并发；懒加载以生产 bundle 和冷启动记录验证。禁止只凭索引名称断言提速。

测试假设：独立 8核/16GB、本地 MySQL/Redis，数据按 1万→10万→100万递增（环境不足时记录实际规模），用户人均3角色、热点城市50%、20%软删除。并发1/20/50，预热30秒，稳定5分钟，重复3次；记录硬件、版本、SQL、p50/p95/p99、吞吐、应用业务错误率、连接池等待。

候选目标：常用分页与待办 p95≤500ms、p99≤1s、业务错误率<0.1%；整页角色查询不随页大小线性增加。不能以 HTTP 200 掩盖业务失败。索引按实际 where + order + tenant_id 设计；缓存按 tenant/role 分片，提交后失效，不允许旧权限因优化长期生效。

前端以生产构建测试慢网、4倍 CPU 降速、冷/热缓存、长列表；新增设计器按路由懒加载，列表和导出分页，导出异步化。性能回归同时验证受限角色，不能通过扩大数据范围提升查询速度。

### 6. BPMN 引擎及设计器

候选首选 Flowable 嵌入式引擎：便于同 Java 事务中处理审批与业务状态；bpmn-js 负责画布和图形查看，服务器负责 XML 校验/部署/权限。自研状态机不满足标准 BPMN 需求；独立工作流服务增加本期运维与跨服务一致性成本。

版本已锁定候选 Flowable 7.2.0：本机实测 JDK 21.0.10 / Maven 3.9.14，backend 解析到 spring-boot.version=3.4.10（不能沿用 README 的 Java17 概述代替实测）。7.2.0 的 BOM 基于 Boot 3.5.4 / Spring 6.2.10，与本项目 Boot 3.4.10 / Spring 6.2 同代，Jar 清单声明 Apache-2.0；隔离测试已在 H2 上完成建表、部署、启动、完成、计时器与引擎重启恢复，Spring 自动配置亦能创建 ProcessEngine。注意 7.2.0 的 `flowable-spring-boot-starter-process` 在干净类路径上缺失 `flowable-spring-configurator` 与 `flowable-app-engine-spring`，必须显式补齐或用全量 starter；9.2 接入时必须保留该回归。8.0.0 面向 Boot 4，不得使用；本批不升级核心框架。

官方当前集成文档 https://www.flowable.com/open-source/docs/bpmn/ch05a-Spring-Boot 页面对应 8.x / Boot 4，不能据此认定最新版本可用于本项目。文档亦提示引擎可能影响 spring.liquibase.enabled，必须确认项目已有 Liquibase 迁移仍正常执行，不能照抄自动建表配置上线；上述测试使用独立 H2，未动项目 schema。

首批节点白名单：开始/结束、用户任务、排他网关、并行网关、受控服务任务、定时边界事件。引擎版本验证后补多实例会签；子流程/调用活动作为后续可启用节点，未实现节点发布时明确拒绝。

模型设计：画布、属性面板、审批人选择器、条件构造器、校验提示、模拟预览、版本差异。支持导入/导出 BPMN XML，但服务端限制文件大小、节点数、禁 DTD/外部实体、脚本和任意表达式/类引用。bpmn-js 自定义属性必须与引擎解析器一致，不能直接套用另一引擎属性面板。

条件由受限结构化规则编译，不把用户输入交给任意 EL；服务任务仅 allowlist 内业务 handler。HTTP 回调未来若开启需域名白名单、签名、超时及 SSRF 防护。

### 8. 表与一致性

引擎拥有运行/历史/任务表，不从业务代码直接更新其内部表。应用侧候选表：

- oa_employee（关联 sys_user）、oa_position、oa_employee_position、oa_delegate_rule。
- oa_process_model、oa_process_release（XML摘要、引擎定义ID、版本、表单版本、可发起范围、发布者）。
- oa_form、oa_form_version；发布快照不可变，字段保存稳定 key。
- oa_application（tenant_id、business_type/key、process_instance_id、发起者/部门快照、form_version、状态、version）。
- oa_approval_audit（动作、任务/实例、操作者/原审批人、理由、时间、请求ID）、oa_cc_receipt。
- oa_attachment_link（文件归属、业务实例、扫描/可用状态）；文件实际由受控存储管理。
- oa_outbox（event_id唯一、聚合ID、负载、状态、重试次数、下次执行时间）；oa_request_dedup（tenant+actor+command+request_id唯一）。
- 各业务独立主/明细表，不把全部业务长期塞进一个无约束 JSON 大表；表单快照可 JSON，金额/日期/统计字段类型化。

业务发起、引擎启动、业务状态、审计及 outbox 在同一数据库事务中提交；若无法共享事务则不得声称原子性，需明确补偿方案后再发布。所有命令幂等键绑定租户、用户与操作；任务版本冲突返回明确结果，不重复扣余额/记支出。

所有 ID 对前端序列化为字符串；金额用定点数及币种，禁止 JS 浮点计算作为财务权威。实例绑定组织及表单快照，人员选择后服务端再确认同租户、有效员工。

引擎查询必须显式带 tenant_id，不能依赖只对 MyBatis-Plus 生效的数据拦截器。候选组名按租户限定；后台作业显式恢复租户上下文。管理员运行维护权限与查看敏感表单权限分开。

### 9. 审批动作语义

- 审批人：指定员工、岗位、部门负责人、发起人主管、受控表单人员字段；配置空审批人时阻止发布或进入人工处理，不默认自动同意。
- 会签：全票、比例及一票否决分别配置；并发完成使用引擎乐观锁与幂等，终止剩余任务必须记录原因。
- 撤回：发起人且尚无有效审批动作可撤回；已处理后通过独立撤销申请，不随意抹去历史。
- 驳回：终止当前申请并保留历史；退回：仅可选已校验的前序人工节点，首批禁止跨并行分支任意回跳。
- 转交/代理：同租户有效员工，代理有时段及范围，禁止环；记录原候选/受理者和实际操作者。代办不等于角色提升。
- 加签/减签：后续复杂流程功能，必须有显式权限、决策阈值规则和完整轨迹，未实现时不显示可执行入口。
- 催办：同任务限频去重，不能重置 SLA。超期定时器与工作日历结合，先明确自然时长与工作时长策略。
- 审批附件：私有桶或经鉴权代理下载；持有裸 fileId/URL 不代表授权，过期链接不可重复使用。不复用公众可读链接承载财务/人事文件。

### 10. 通用 OA 全景与流程模板

| 批次 | 业务          | 最小闭环 / BPMN 模板                                                 | 明确边界                                                                   |
| ---- | ------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| D    | 请假          | 草稿→主管→按天数条件人事复核→批准扣减额度；驳回/撤回释放占用         | 假期类型、工作日历、跨日时段、余额并发校验；法规规则由管理员配置而非硬编码 |
| D    | 报销          | 明细/附件→主管→财务→按金额条件终审→待支付→人工登记支付               | 审批通过不等于已付款；不接银行，发票验真首版人工核验                       |
| E1   | 出差/借款     | 计划预算→主管/财务→核准→关联报销及核销                               | 借款余额、重复核销和超预算复核                                             |
| E1   | 假勤          | 排班、签到记录、补卡/加班/外出申请→主管→人事                         | 首版手工/受控导入考勤，不含打卡机、定位、人脸或薪资计算                    |
| E2   | 采购          | 申请→部门→预算/财务→采购执行→验收                                    | 审批与执行分状态；采购完成关联资产入库                                     |
| E2   | 资产/用品     | 台账、入库、领用、归还、调拨、报修、盘点、报废                       | 数量与归属变动可追踪，库存事务防负数                                       |
| E3   | 合同/用印     | 合同草稿→法务/财务会审→负责人→签署登记→归档；用印申请→授权保管人执行 | 电子签章为外部集成，不用图片签名冒充法律签章；到期提醒                     |
| E3   | 公文/知识     | 拟稿→审校→审批→发布→指定范围签收/阅读                                | 可见范围、版本和附件授权；撤稿不删除审阅轨迹                               |
| E4   | 会议室        | 预约→冲突校验→按配置审批→确认/取消                                   | 审批等待期间占用策略明确，到时超时释放；并发防重复预订                     |
| E4   | 车辆          | 用车申请→主管→调度指派→出车/归还/费用登记                            | 车辆/司机冲突、停用维保，不接外部车联网                                    |
| E4   | 日程/工作报告 | 个人/部门日程、日报周报、汇总、提醒                                  | 不默认 AI 读取敏感文件；既有 App 工作汇报不跨身份直接拼接                  |
| E5   | 报表/运维     | 审批时效、超期、业务金额/数量统计、导出、失败任务重试                | 租户/部门过滤，敏感字段脱敏；导出异步与过期清理                            |

BPMN 用于需审批的业务，普通 CRUD/看板/搜索不强行编排为流程。每个 E 子批次有独立表单、流程模板、权限、状态机、页面、接口及集成测试，不能只建通用表和菜单就标「整套完成」。

### 11. 自测与交付门槛

- 单元：连接返回模型、定时器、旧事件、单飞、游标、ID、幂等、审批规则。
- 集成：真实测试 MySQL/Redis 和引擎 schema；事务回滚、并发审批/已读、跨租户/越权、附件、定时器重启恢复。mock 不能替代这些结果。
- 界面：启动开发服务，浏览器操作普通/受限账号，检验成功与失败路径、深链、375px 溢出、表单校验、BPMN 保存/再打开/部署。
- 移动：H5 浏览器可验证运行时联调，但不等价微信真机；鸿蒙必须有签名包、真机、日志与冷启动结果。
- 性能：按第5节独立基线，业务功能正确后再调索引/缓存，输出优化前后数值而不是「最佳」。
- 构建：分别执行各仓真实 scripts/测试开关，后端注意 compile 自动格式化，禁止把格式改动混入功能；不跳过钩子。
- 推送：仅完成且验收的批次按依赖先子仓后父指针；记录提交ID、工作区和远端差异。存在本批必需联调阻塞时保留未完成状态，不声称零问题。

## Risks / Trade-offs

- [范围大] → 全景明确但逐闭环发布，待办不折叠为一个已完成项。
- [原生能力缺失] → CLI 管理、真机验收，缺环境时停止对应完成声明。
- [BPMN 表达式执行权限] → 设计者权限与执行权限分离，节点/表达式白名单，服务端 XML 校验。
- [租户数据越权] → 业务、引擎、附件、缓存、异步任务分别验证隔离。
- [审批与财务状态混淆] → 审批通过、实际支付、入库、签署分开建模与授权。
- [性能优化削弱权限] → 权限回归是压测的前置，不允许移除过滤换取速度。
- [并发会话修改仓库] → 每批前重新核查 diff/远端，不覆盖未知工作区，不强推。

## Migration Plan

1. 先修消息连接和单飞测试；确认 API 改动的客户端发布顺序，保持现有数据。
2. 在独立测试库验证引擎/新表迁移及备份恢复；生产 schema 由经批准的迁移执行，应用启动不擅自升级引擎表。
3. 添加员工/流程/表单/OA业务表、菜单和权限，默认不赋予所有现有用户审批/流程发布权限。
4. 导入仅面向测试组织的请假/报销模板，验证双租户和多角色，再启用目标组织。
5. 发布后旧实例保留旧定义，后续版本只承接新实例。回滚应用需兼容已部署 schema；有在途流程时禁止删引擎表或强降版本，优先向前修复。
6. 全景其余业务逐批迁移和验收；提交推送不代表生产部署。
